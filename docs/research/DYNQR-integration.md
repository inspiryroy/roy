# INSCREEN 怎样在各国生成动态国家码并确认到账

检索日期 2026-10-18。本轮用了 10 次 WebSearch（预算已用完）。WebFetch 对 BRI、BCA、payOS、PayMongo、SCB、SePay 都返回 DNS 失败，所以本文依据搜索摘要，加上 `docs/research/*.json` 中已核实的条目和同轮 `devices.json`、`pain.json` 的结果。每条事实的类型（已核实 / 公司声明 / 推论 / 记忆·未核实 / 未查到）、置信度和来源见 `integration.json`（INTEGRATION-01～47）。

## 一句话结论

INSCREEN 能显示动态码，但这不是瓶颈。真正卡住的是两件事：**谁有权签发这张码**，**谁能给出付款人改不了的到账确认**。印尼、马来西亚、菲律宾、泰国商户码（tag 30）、新加坡 NETS 码只能由收单方签发，INSCREEN 在这些地方只是收单方 API 的一块屏。创始人设想的“0% 手续费、直连账户”只在**越南**和**柬埔寨**有现成的技术和合规路径，而且这条路径和“外国钱包跨境锁价收款”互相冲突。

## 三种码，三种做法

| 类型 | 例子 | 终端能否自己生成 | 到账确认 |
|---|---|---|---|
| ① 收单方签发的商户码（模式 a） | QRIS（带 NMID）、DuitNow（码内账户号约 60 秒有效，低置信）、QR Ph tag 28、泰国 tag 30 Biller、SGQR NETS（带签名） | 不能，要调收单方 API | 收单方回调或查询 API |
| ② 账户型转账码（模式 b） | VietQR + 金额 + 附言、PromptPay tag 29、KHQR、PayNow UEN | 能，格式公开 | 要另找银行入账通道 |
| ③ 静态 QRIS 插入 tag 54 | 开源库做法 | 能付，但不能对账 | 不可用 |

## 跨境：外国钱包能不能付

- 已核实：泰国中国线只受理 6 家参与银行的**商户码**；马来西亚 DuitNow 商户自动受理跨境；菲律宾 Alipay+ 可付全国 QR Ph 商户，商户不需换码；柬埔寨有 12 个 Alipay+ 钱包；越南自 2026-04-03 起，Alipay 可扫“NAPAS 网络内受理点”的 VIETQRGlobal，个人账户能否算受理点未说明。
- 码要满足的条件（推论）：必须是 P2M 模板（泰国用 tag 30/31，不用 29；马来西亚 MCC 不能是 0000；菲律宾用 tag 28，不用 27；新加坡用 UEN 或 NETS，不用手机号；柬埔寨用 tag 30；印尼要有 NMID），并带真实 MCC、商户名和参考号。动态码要带过期时间，锁汇有效期必须短于码有效期。
- 本轮**没有找到**现有跨境线拒绝或明确受理动态码的证据。终端自己生成的个人账户码大概率进不了跨境受理，INSPAY 网络本身也默认拒绝 P2P。所以模式 b 的商户收不到 PayPay 等外国钱包的锁价付款，除非它同时有一张收单方签发的商户码。

## 对 INSCREEN 的含义（推论）

1. 模式 a 国家（印尼、马来西亚、菲律宾、泰国商户码）：动态码和回调都是收单方的能力，INSCREEN 没有差异化，费率和商户关系也归收单方。INSPAY 的价值在于“多国收单 API 聚合 + 统一到账确认 + 对账和开票 + 经 P2M 码的跨境锁价”，收入来自设备或 SaaS 费，或向收单方分润。
2. 模式 b 国家（越南、柬埔寨）：INSPAY 能掌握码和确认链路，真正可以做“0 费率直连账户”。但越南已有约 USD 23 的 SePay 音箱，INSCREEN 要靠屏幕上的开票和对账功能取胜。读取入账只能走银行正式 API，不能转发短信或托管网银密码。
3. 稳定币：越南、泰国、印尼都不允许经本地 QR 收单把稳定币兑成本币入商户账户，INSCREEN 上的稳定币受理只能放在离岸或游客沙盒里（细节见 docs/11）。
