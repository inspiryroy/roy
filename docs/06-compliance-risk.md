# 06 · 合规结构与风险

> 本章是技术方案对法律结构的**工程化假设**，用于设计系统边界；每一条标注"需律师确认"的结论都必须在实施前取得对应司法辖区的正式法律意见。事实依据与日期见 [09-sources.md](09-sources.md)。

## 6.1 设计原则

1. **稳定币不碰终端用户与商户**：用户付日元、商户收本币；稳定币只在持牌机构之间作为结算资产。
2. **本币在境内兑换**：泰铢、林吉特、印尼盾、越南盾、基普等存在离岸交割限制的货币，只由境内持牌银行/机构兑换和入账。
3. **每段资金流都有持牌主体**：用户↔钱包（日本资金移动业者）、钱包↔网络（新加坡枢纽须持 MPI 牌照，或把稳定币兑换与托管交给持牌机构，见 6.3）、网络↔LSP（目的国持牌参与者）、稳定币兑换（各地持牌 VASP / 稳定币发行方机构通道）。
4. **结算资产可替换**：监管变化时，同一套净额与对账流程可降级为法币电汇执行。
5. **稳定币只到可落地的伙伴**：新加坡、菲律宾的伙伴链上收 USDC；泰国、马来西亚、印尼、越南、柬埔寨、老挝的伙伴收工作日 USD 电汇，其净退款也经离岸出金方以电汇回收，不向其收取稳定币（柬埔寨银行层持有稳定币须 NBC 批准，获批前同样走电汇）。这六国是否经 USDC 中转，由 [10 章](10-economics.md) 10.6 的法币基准对照决定。

## 6.4 反洗钱、制裁与 Travel Rule

* **KYC 依赖**：用户 KYC 由 PayPay 完成（PayPay 海外模式要求出国前完成 eKYC）；网络对 MPP 做机构尽调，并在合同中约定 KYC 依赖与数据提供义务；
* **发起人信息**：pay 请求携带最小必要的发起人信息；网络传给 LSP 的只有付款人姓名、国家、网络内部 `payerRef` 与发起钱包机构，按目的国跨境支付的信息要求（FATF R.16 及各国外汇申报）执行，个人数据跨境见 6.7；
* **制裁筛查**：付款人（MPP 侧已筛）、商户名/账户（网络侧筛 + LSP 侧筛）、LSP/LP 的链上地址（链上分析工具）；
* **交易监控**：同一用户短时间多笔、同一商户账户异常的跨境收款集中、整数金额、深夜大额等规则；
* **Travel Rule**：网络与 LP、出金方及链上伙伴（新加坡、菲律宾）之间的每笔稳定币转账前发送 IVMS101 信息（经 TRUST/Notabene/Sygna 等互通方案）；电汇伙伴不收稳定币，不涉及链上 Travel Rule；
* **限额复刻**：各条既有跨境 QR 线的发卡侧限额（如马来西亚出境 RM3,000/笔、香港 HK$10,000/日）作为参照，网络对每个国家/通道设置单笔、单日、单月限额，并支持 MPP 覆盖更严格的限额。

## 6.5 消费者保护与争议

* 显示：商户名 + 本地语言名 + 国家、当地币金额、日元金额、汇率与全部费用（PayPay 现行做法是"网络汇率 + 3.85%"）；
* 退款：国家快速支付系统多数没有退款报文，退款走"商户反向贷记 → LSP → 网络 → MPP"，汇率规则在 MPP 合同中写明（见 03 章 3.4）；
* 贴码诈骗：**商户名查询回显是 Phase 1 必需项**（泰国很多商户码不带 tag 59）——identify 时同步向 LSP 查询（[07 章](07-api-spec.md) 7.4.0，参考实现尚未实现），查不到商户名时提示用户人工核对，并对该码执行首笔限额；另有商户账户黑名单（与 LSP 共享）、新商户首笔限额、地理位置与码国家一致性校验；发现诈骗后的处置流程待补；
* 无卡组织式 chargeback：在用户条款中明确争议处理路径与时限。

## 6.7 个人数据跨境

| 环节 | 工程化假设 | 依据 / 状态 |
|---|---|---|
| 日本（PayPay → 网络 → LSP） | PayPay 把付款人姓名、居住国、KYC 等级等提供给境外网络，网络再把其中一部分传给目的国 LSP，属个人信息保护法第 28 条"向外国第三方提供"：须取得用户同意（同时告知接收国的个人信息保护制度与接收方的保护措施），或由接收方建立符合标准的同等体制；网络与 PayPay 签数据处理协议，明确是"委托"还是"第三方提供" | **需日本律师确认**；在此理顺前 PayPay 法务很可能不放行接入（推断） |
| 目的国 | 越南个人数据保护法（Law 91/2025/QH15，2026-01-01 生效：跨境传输须做影响评估并于 60 天内报公安部）、泰国 PDPA、印尼 GPN 境内处理要求、菲律宾 DPA，逐国确认 | 越南、印尼的要求有调研依据（印尼 GPN 见 6.3）；泰国 PDPA、菲律宾 DPA 的具体要求本轮未调研——**需各目的国律师确认** |
| 最小化 | LSP 只收付款人姓名、国家和网络内部 `payerRef`；KYC 等级等其他信息只留在网络侧用于风控；保存期限与删除流程写入合同 | FATF R.16 已于 2025-06 修订（各国 2030 年底前落实）；"跨境支付超过 USD/EUR 1,000 时须随附付款人姓名等信息"的门槛来自记忆，**未核实**，须对照 R.16 / INR.16 原文；低于门槛时能否省略姓名，待各国落实规则确认 |
